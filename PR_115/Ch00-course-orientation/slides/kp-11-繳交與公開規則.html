情境引入 | Scenario

🧑‍🎓

👨‍🏫
教授：「private 階段防的不是我看到，是防「其他組」看到。」
🧑‍🎓
研究生：「那截止後呢？一直 private 不行嗎？」
👨‍🏫
教授：「不行。教師端 AI agent 沒辦法評分一個它進不去的 repo。忘記轉 public，等同沒交。」

1同一個 repo，兩個階段 | One Repo, Two Phases

截止前建議 private，截止後須轉 public——一個 repo，經歷兩種身分。
🔀 圖 1：Private → Public 兩階段設計

2為什麼要先 Private？| Why Private First

若所有組別 repo 從第一天就公開，寫得快的組別會被落後組別直接參考、甚至照抄——不一定是刻意抄襲，但「就在那裡、看得到、複製貼上很方便」本身就會製造大量灰色地帶爭議。

private 階段把這個誘惑跟爭議直接關掉：你的組看不到別人的，別人的組也看不到你的，大家在同一個起跑點上獨立開發。

3為什麼截止後必須轉 Public？| Why Public After Deadline

教師端 AI agent 的五個評分面向——功能正確性、Git 使用品質、AI 使用透明度、程式碼品質、文件完整性——每一項都需要實際打開程式碼、commit 歷史、PROMPTS.md 才能檢視。

⚠ 逾期未轉 public，視同「未繳交」

就算程式碼早已寫完、commit 紀錄漂亮、README 完美，只要忘記把 repo 從 private 切成 public，這份心血在系統裡就等同「沒交」。

不是刁難，是技術限制

看不到的東西，沒辦法評分。「轉為 public」是繳交流程中不可省略的最後一步。

4實務建議：提前演練切換動作 | Practice the Switch Early

1
截止日前一天先演練

用測試分支或跟組員說好分工，先演練一次整個切換動作。

2
確認連結不會失效

檢查 README 裡的雲端影片連結，轉換後是否依然可讀取。

3
截止日當天照表操課

只需按下早就演練過的按鈕，而不是在毫無經驗的情況下摸索。

截止日深夜十一點五十九分才第一次嘗試轉換，跟提前演練過一次，壓力感受完全不同。

知識檢定 | Knowledge Check

1
規則理解
開發期間建議 private 的真正原因是什麼？防的是誰看到？
✅ 正確答案：
防的不是老師看到，是防其他組看到，用以降低組間抄襲風險，讓所有組別在同一起跑點上獨立開發。
2
後果判斷
某組程式碼截止前就寫完、commit 紀錄完整，但忘記把 repo 轉為 public，會有什麼後果？
✅ 正確答案：
視同未繳交。教師端 AI agent 無法 clone 到 private repo 的內容，即使程式碼品質再好也無從評分——「轉為 public」是繳交流程不可省略的一步。
3
實務應用
為什麼建議在截止日前一天就先演練一次 private → public 的轉換？
✅ 參考答案：
提前演練可以確認轉換流程本身是否順利、README 裡的雲端連結轉換後是否依然有效，避免在截止日深夜才第一次嘗試而手忙腳亂，甚至因操作失誤導致逾期未轉 public。

總結回顧 | Summary

private 階段保護你不被抄襲，public 階段讓你被公平評分——兩件事同等重要，缺一不可。
記得在截止後轉為 public，是整個繳交流程裡最後、也最不能忘記的動作。
